2. Authoritative persistence model

  • One encrypted SQLite database per company is the V1 target; Drift provides typed access and migrations.
  • UUIDs are used for records that can be created offline; human-readable codes/numbers are separate.
  • Money is integer paise; quantities use fixed-point integers with a scale still requiring owner decision.
  • Operations are append-only and tables are projections; audit, file exchange and LAN sync use the same operation model.
  • Stock and ledger balances are derived from posted vouchers and may be rebuilt.

5. Indexing strategy

  • Voucher: company/date/type/series/number.
  • Party/item: normalized search keys plus barcode/code/GSTIN where applicable.
  • Outstanding: party/due-date/status.
  • Stock: item/godown/batch.
  • Audit: entity/entity_id/time.
  • Operations: company/device/sequence/apply state.
  • Imports: batch/status/error severity.

6. Migration specification

  1. Read current schema version.
  2. Open protected backup/recovery point before material migration.
  3. Run numbered migration in a transaction where practical.
  4. Validate invariants and derived-data rebuild fixtures.
  5. Commit new schema version only after validation.
  6. Record migration result and application build.
