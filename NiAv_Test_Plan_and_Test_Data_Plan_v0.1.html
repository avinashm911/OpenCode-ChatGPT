7. Test-data safety

  • Use synthetic customer/financial data; no real secrets in fixtures.
  • Mark golden fixtures immutable by version and record expected outputs.
  • Each import corpus includes valid, boundary, duplicate, malformed and adversarial cases.
  • Retain fixture version alongside test result and application/database schema version.

8. Entry/exit criteria

Entry: requirements/design IDs stable enough to test, fixture version available, build reproducible. Exit: planned tests pass, critical defects closed/accepted, evidence archived, migration/backup/restore verified, release checklist signed.

Living-document protocol

  1. Trace every material change to its upstream source/decision ID.
  2. Do not overwrite unresolved TBD/VERIFY/open items; resolve them with an owner decision or verification record.
  3. Preserve stable IDs when wording or implementation changes.
  4. When a source changes, revalidate affected rows before baselining the child document.
