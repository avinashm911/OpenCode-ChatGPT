2. Design principles

  • Offline-first local core; internet is not a prerequisite for core accounting/inventory operation.
  • Authoritative transactional data is separated from rebuildable derived data.
  • Money and quantity behavior is deterministic; unresolved methods remain open.
  • Every external/file input crosses a validation/security boundary.
  • File-first workflows are first-class; direct API automation is an adapter, not a prerequisite.
  • Security controls must degrade/recover safely and must not destroy customer data.

Rejected/ReturnedAction stopped or sent back with reason; correction creates a new valid transition.
PostedAuthoritative accounting/stock effect exists; later correction follows permitted alteration/reversal rules.
Cancelled/ReversedEffect is neutralized through an auditable operation, not silent deletion.
ImportedBatch passed validation and commit; source/batch references retained.

7. Import design

  1. Select source file and identify adapter/template version.
  2. Parse into an isolated import model; reject malformed or oversized input.
  3. Resolve mappings and references against company masters.
  4. Run structural and business validation.
  5. Generate preview/error report with row/field reasons.
  6. Commit atomically according to selected mode; record batch identity and source reference.
  7. Reconcile source totals and retain migration evidence.

8. Sync design

  • Each operation has stable operation ID, device identity and sequence/dependency information.
  • Host rechecks authorization, locks, series and approval rights at apply time.
  • Duplicate/replayed operations are idempotently rejected or ignored.
  • Conflicts are surfaced; no silent destructive merge.
  • Remote file exchange uses the same operation-batch semantics when enabled.

9. Security design

  • Credentials/secrets remain outside ordinary exported business data.
  • Audit history is append-oriented and protected from ordinary editing.
  • Backup payloads are encrypted/authenticated according to SEC design decisions.
  • Imported files, sync peers and restore payloads are untrusted until validated.
  • Licence state gates features without deleting data.

10. Error-handling model

ClassRequired behavior
Input errorInline field error; preserve user-entered data where safe.
Business-rule errorBlock transition and identify rule/field causing failure.
Permission errorReject server/host/application command regardless of UI visibility.
Import errorRow/field error report; no unintended partial commit.
Sync conflictPersist conflict context and present resolution path.
Integrity/security errorQuarantine/reject input; retain diagnostic evidence without exposing secrets.
