6. Design

6.1 UX principles

  1. Language first: every string, message, date/number format and print template is localised; users can switch language at runtime.
  2. Few taps to money: the most frequent task (cash bill) is reachable from the home screen in one tap and finishes in as few taps as possible.
  3. Show only what is needed: Simple mode hides advanced fields and menus; users and owners can hide/reorder screens and fields (REG M23).
  4. Forgiving: undo/cancel with reason instead of delete; confirmations only for irreversible actions; autosave drafts.
  5. Readable on cheap phones: large touch targets, high contrast, large-text option, no reliance on hover or colour alone.
  6. Terminology that matches shopkeepers: an optional simplified-terms mode (REG M02.8), reviewed with native speakers (ZCP §8).

6.2 Information architecture (navigation)

  • Home: customisable tiles (New Bill, Receive Payment, Stock, Reports, Parties, Day Summary), search bar always visible, quick-switch of company.
  • Bottom navigation (proposed): Home · Billing · Parties & Items · Reports · More.
  • More: Vouchers (all types), Masters, Import/Export, Backup, Users & Admin, Settings, Licence, Help.
  • Global search reachable from every screen (M12).
  • Voucher screens share one layout pattern: header (type, series, number, date, party) → lines → totals/taxes → payment/narration → actions.

7.4 Data architecture

  • Store: one encrypted SQLite database per company (SEC §5.1). Drift for typed access and migrations.
  • Primary keys: UUIDs for every record that can be created offline; human-readable codes are separate fields.
  • Money: integer paise. Quantities: fixed-point integers with a defined scale (scale value to be decided, D-M4). No floating point anywhere in accounting.
    Resolved: Money INTEGER paise. Quantity INTEGER x10^4 (per-unit display precision: pcs 0, kg/litre 3, other <=4). Line amount = round-half-up(qty x rate / 10^4); invoice round-off separate ledger line to nearest rupee. Stock value in paise; unit cost derived. IDs UUIDv7 TEXT. Dates ISO TEXT; timestamps INTEGER epoch ms UTC (Decided: proposed value)
  • Rounding: one central, tested rounding service (invoice round-off, tax rounding rules [VERIFY GST rounding rules]).
  • Dates/time: stored as ISO date and UTC timestamps; display in IST; financial-year aware.
  • Operation log (from day one): every change appends {op_id, device_id, seq, timestamp, entity, action, payload}; tables are projections of the log. The same log powers audit, file exchange and LAN sync (ZCP §6.2).
  • Audit hash chain: each audit/voucher record links to the previous record's hash (SEC §7).
  • Derived data: stock and ledger balances are computed from posted vouchers and cached in summary tables that can be rebuilt (Admin "rebuild" utility, REG M18.9).
  • Schema versioning: every release carries migrations; downgrade is refused (SEC §4).
  • Indexes on date, party, item, voucher type/series/number and search keys; pagination for all lists.

7.6 Search architecture

A local search index (SQLite full-text if the bundled build supports it [VERIFY], otherwise an in-memory index built at start and updated incrementally). Normalised keys per script; prefix and partial matching; recents/pins ranking; index updates happen in the same transaction as the data change. Target latency and dataset size to be set (O-M03) and tested with generated data.

7.7 Sync architecture (multi-user)

Host device + client replicas over shop Wi-Fi/hotspot (ZCP §6). Operation-log exchange, device-owned voucher series, host-side re-validation, Conflicts queue, QR pairing with TLS pinning (SEC §6). Staged: file transport first (Gate S1), then LAN sync (Gates S2, S3). Sync is R1b.

7.8 Licence and trial subsystem

Offline signed keys, request code, trial anchoring, trusted-time, denylist, entitlements service (ZCP §7; SEC §3). Verified at several call sites, not one flag.

7.9 Security architecture

Encrypted DB and backups, Keystore-wrapped keys, PIN/biometric, signature self-check, obfuscated release builds, audit hash chain, role rights, safe import/export (SEC §4 to §8).

7.10 Print, export and file services

PDF and ESC/POS renderers driven by the same template model; Excel/CSV via a shared table-export service with formula-injection protection (SEC §8); backups via a versioned container format with authenticated header (SEC §5.4).

10. Engineering approach and quality
